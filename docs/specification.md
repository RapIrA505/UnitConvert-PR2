# Техническое задание — UnitConvert

Практическая работа № 2. Команда «Крутые перцы». Разработчик: Молдаванский Р.Д. Назначенный тестировщик: Белов А.М.

## 1. Назначение и состав

Небольшое настольное приложение Python 3.12 / Tkinter переводит температуру, длину и массу между двумя единицами. Все шесть вычислений — отдельные чистые функции модуля `core.py`. Интерфейс `app.py` содержит выбор преобразования, поле числа, кнопку «Перевести» и строку результата. Сеть, база данных и авторизация не нужны.

## 2. Функциональные требования

| ID | Функция | Формула | Область входных значений |
|---|---|---|---|
| F1 | `celsius_to_fahrenheit(c)` | `c × (9 / 5) + 32` | `c >= −273.15` |
| F2 | `fahrenheit_to_celsius(f)` | `(f − 32) × (5 / 9)` | `f >= −459.67` |
| F3 | `km_to_miles(km)` | `km × 0.621371` | `km >= 0` |
| F4 | `miles_to_km(mi)` | `mi / 0.621371` | `mi >= 0` |
| F5 | `kg_to_pounds(kg)` | `kg × 2.2046226218` | `kg >= 0` |
| F6 | `pounds_to_kg(lb)` | `lb / 2.2046226218` | `lb >= 0` |

Коэффициенты F3–F6 — именно указанные десятичные значения; тесты сравнивают результат с этими значениями, а не с иным округлением физических коэффициентов. Внутренний результат не округляется. Формат отображения в GUI — до восьми значащих цифр.

## 3. Валидация и ошибки

- API `core.py` принимает только конечные `int` и `float`; `bool`, строки (в том числе числовые), `None`, списки и прочие типы вызывают `TypeError`.
- `nan`, положительная и отрицательная бесконечность вызывают `ValueError`.
- Числа ниже допустимой границы вызывают `ValueError`. Сама граница допустима: обе температуры абсолютного нуля, а также нулевая длина и масса. Значение `−0.0` допустимо.
- Если преобразование огромного целого к `float` или арифметика результата переполняются, функция вызывает `ValueError`; бесконечный результат не возвращается.
- GUI преобразует введённый текст в число перед вызовом API. Допускаются десятичная точка и запятая, внешние пробелы и запись с экспонентой. Пустой или некорректный ввод отображает ошибку, окно продолжает работать.
- После ошибки можно ввести новое число и получить результат. Нажатие Enter эквивалентно кнопке.

## 4. Контрольные примеры

`0 °C → 32 °F`; `212 °F → 100 °C`; `1 км → 0.621371 мили`; `0.621371 мили → 1 км`; `1 кг → 2.2046226218 фунта`; `2.2046226218 фунта → 1 кг`. Числовые модульные проверки используют `pytest.approx` с относительной и абсолютной погрешностью `1e−10` (кроме отдельно обоснованных проверок очень малых значений).

## 5. Версии и организация проверки

Учебная версия 1.0 сохранена отдельно в `versions/v1_0/core.py`. Ровно одна из шести функций намеренно содержит вычислительный дефект: F2 использует `5 / 8` вместо `5 / 9`. Версия 1.1 в корне исправляет F2. Остальные функции и правила валидации идентичны.

Белов А.М. указан как тестировщик проекта при учебном распределении ролей; готовые материалы предназначены для передачи ему. Автоматические прогоны выполнены при подготовке материалов, факт личной передачи и ручного выполнения другим студентом не утверждается.

`tests_initial` фиксирует исходные обычные и ошибочные сценарии. Этот набор должен выявить дефект 1.0 и пройти на 1.1. Cosmic Ray автоматически изменяет только `core.py` версии 1.1 в изолированной копии; ни GUI, ни тесты не мутируются. После первого прогона анализируются реальные выжившие мутанты и добавляются `tests_improved`. Второй прогон выполняет оба набора. Доли покрытия строк и ветвей считаются отдельно; мутационный показатель — число убитых мутантов, делённое на число сгенерированных мутантов. Неработоспособные и эквивалентные мутанты, если появятся, описываются явно.

## 6. Приёмка

Все шесть преобразований соответствуют таблице, ошибки не приводят к падению интерфейса, итоговые тесты проходят, сохранены исходный дефект, исправление и воспроизводимые результаты двух мутационных прогонов. Приложение запускается командой `python app.py` без сторонних библиотек; инструменты тестирования устанавливаются отдельно.
