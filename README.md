# UnitConvert — практическая работа № 2

Простой конвертер единиц на Python / Tkinter: °C ↔ °F, километры ↔ мили, килограммы ↔ фунты. Разработчик — **Молдаванский Р.Д.**, назначенный тестировщик — **Белов А.М.** Команда — **«Крутые перцы»**.

В корне находится исправленная версия **1.1**. Учебная версия **1.0** с единственной намеренной ошибкой сохранена отдельно. Материалы подготовлены для обмена проектами и проверки; личный обмен между студентами не подтверждается автоматическими логами.

## Запуск

Нужен Python 3.12 или новее с Tkinter (обычная установка Python для Windows). Сторонние библиотеки для приложения не требуются.

```powershell
python app.py
```

Выберите преобразование, введите число, нажмите «Перевести» или Enter. Допускаются десятичная точка или запятая. Температура ниже абсолютного нуля и отрицательная длина/масса запрещены. Неверный ввод выводит понятную ошибку.

## Повторить проверку

Репозиторий: [RapIrA505/UnitConvert-PR2](https://github.com/RapIrA505/UnitConvert-PR2). Из корня скачанного проекта создайте окружение и установите зафиксированные версии инструментов:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tools/verify.py
```

`verify.py` запускает исходные тесты на сохранённой версии 1.0 в отдельном каталоге и ожидает обнаружения дефекта. Затем запускает оба набора на 1.1. Файлы приложения не меняются. Для простого запуска итоговых тестов достаточно `.\.venv\Scripts\python.exe -m pytest -q`.

Для повторения двух сессий мутаций используйте новый каталог результатов:

```powershell
.\.venv\Scripts\python.exe tools/mutate.py initial --output-dir verification/recheck
.\.venv\Scripts\python.exe tools/mutate.py improved --output-dir verification/recheck
.\.venv\Scripts\python.exe tools/summarize.py --output-dir verification/recheck
```

Укажите другое имя каталога для следующего независимого повторения: программа сохраняет уже существующие базы и отказывается их перезаписывать. `summarize.py` берёт мутации из указанного каталога, а результаты модульных тестов из `verification/test_summary.json`, созданного `verify.py`; временные копии после проверки не нужны для чтения сохранённых результатов. Cosmic Ray автоматически генерирует все стандартные мутации только `core.py` версии 1.1, исполняет исходные/расширенные тесты и сохраняет базу, диффы и вывод каждого запуска. Итоговый `core.py` защищён изоляцией копии и сравнением SHA-256. GUI и тестовый код не входят в область мутаций и покрытия.

Проверенная среда: Windows 11 Pro 10.0.26200 x64, Python 3.12.14, pytest 9.1.1, coverage 7.16.2, Cosmic Ray 8.7.0. На машине подготовки системный WMI выдавал ошибку при получении метаданных ОС. Скрипты проверки подключают `tools/runtime_compat/sitecustomize.py`, который выбирает штатный резервный путь CPython для метаданных Windows. Это не меняет вычисления, условия тестов или результаты сравнения. При обычном запуске приложения этот модуль не подключается.

## Где смотреть результаты

Сводка проверок — `verification/test_summary.json`; мутаций — `verification/mutations_initial_summary.json` и `verification/mutations_improved_summary.json`; подробное сопоставление — `docs/mutation_analysis.md`. Отказы учебной версии 1.0 являются ожидаемым обнаружением дефекта, а не ошибкой итоговой версии.

Две фактические проверки интерфейса записаны в [gui_smoke.json](verification/gui_smoke.json): `100 °C → 212 °F` и ошибка при вводе `100ф`. Скриншоты: [преобразование](verification/screenshots/ui_conversion.png), [ошибка ввода](verification/screenshots/ui_invalid.png). Эти проверки GUI считаются отдельно от модульного покрытия и мутаций `core.py`.
